시작자 Winner 팝업 5초 지연 실제 원인 수정

실제 원인:
- localWinnerLatch는 당첨공이 들어가는 순간 이미 만들어지고 있었음.
- 하지만 renderWinner()가 ui() 안에서만 호출되고 있었음.
- 시작자 화면은 물리 진행 중 poll()을 일부러 쉬게 만들어둔 구조라 ui()가 몇 초 동안 호출되지 않을 수 있었음.
- 그래서 시작자는 당첨 결과를 이미 알고 있어도 Winner DOM을 그리는 함수 자체가 늦게 실행됨.
- 관전자는 서버/프레임 업데이트로 ui 상태가 계속 갱신돼 오히려 팝업을 먼저 볼 수 있었음.

수정:
1. requestAnimationFrame draw()에서 drawFrame() 직후 renderWinner()를 매 프레임 호출.
2. 시작자 로컬 당첨 latch가 생긴 다음 프레임에 바로 Winner 팝업 표시.
3. 시작자는 서버 응답 / ui() / poll()을 기다리지 않음.
4. 시작자 hostLatch에 인위적 대기시간 없음.
5. 경기 초기화 시 모든 화면 팝업 삭제 기능 유지.
6. 관전자 중계, 원래 공속도, 마지막 당첨공 연출은 그대로 유지.

이 수정의 핵심은 '당첨 판정'이 아니라 '팝업 렌더 호출 주기' 문제를 고친 것.
